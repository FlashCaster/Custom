## 2. 精确语义

### 2.1 后端增量契约

- **PUT /paths/{path_id}**：path 不存在 → 404；status 非 draft → 409；body 经 `planner.validate_candidate_path({"title": body.title, "stages": body.stages})` 复用 G3-4 全部校验（坏 JSON/缺字段/难度越界/超长/非预期结构 → 400）→ `store.update_path` → 200 + get_path（status 仍 draft，改后仍需 activate）。
- **POST /paths/{path_id}/complete**：不存在 → 404；`set_path_status("done")` 幂等（重复调用 200）；不强制先 activate（任意状态可直接 done，用户确认语义即可）。
- **静态伺服**：`app.mount("/", StaticFiles(directory="frontend", html=True))` 挂在全部 API 路由之后（FastAPI 先匹配路由后落 mount）；GET / → index.html；缺文件 → 404。

### 2.2 前端状态机与交互

- **首屏分流**：库里有 active path → 执行视图（左导航 + 主区 + 进度条）；否则 → 新目标表单（一句话目标 + 兴趣点逗号分隔）→ POST /goals → [生成候选] → POST generate → 候选编辑视图。
- **候选编辑视图**：渲染为可编辑表单——每 stage 一个卡片（标题输入框）；每 task 可编辑 title/brief/quiz.q/quiz.options 逐项/acceptance 逐项，可删除 task 或整 stage；[确认并激活] = 用户改过 → 先 PUT 再 activate，未改 → 直接 activate。
- **执行视图**：左侧 stages→tasks 树（完成打 ✓，当前任务高亮置顶）；主区按 task.kind 渲染——quiz：q + options 单选（radio 提交索引 int，走判分双模 int 分支）+ [提交]；artifact：brief + acceptance 复选框 + [提交]；提交后展示 result（对错 + explanation/evidence）与 recommended_difficulty；右上角进度条 = GET /paths/{id}/progress（percent 宽度 + 百分比 + 当前阶段名）。
- **完成态**：progress.percent==100 → 显示 [标记完成] → POST complete → done 横幅；export 入口（GET /export 下载）。
- **XSS 红线**：所有动态文本（LLM 内容/用户输入）一律走 `escapeHtml` 转义函数或 textContent 渲染，**禁止 innerHTML 拼接**；app.js 加载时 `console.assert` 自检转义函数。

### 2.3 前端测试策略（决策）

- 前端零框架零构建，不引入 node 测试链（守"零依赖"哲学）→ 不以 pytest 测前端；出口 = **K1-K7 手动走查清单 + 可视化审核**（用户规则：可预览成果先审后拍板）。
- 后端新增（update_path / PUT / complete / 静态伺服）仍全 TDD（pytest 红→绿）。

### 2.4 视觉风格规范（风格迭代 v2 —— 还原 DeepTutor 参考截图）

风格来源：用户提供的参考截图（DeepTutor，2026-08-20）。整体气质 = **纸感编辑风**：近白背景 + 发丝线圆角卡片 + 衬线大标题 + 细线图标 + 柔和 periwinkle 主动作 + 大留白。全部 token 以 CSS 变量落 `index.html` 的 `:root`（零框架零构建，不引 UI 组件库）。

| --bg-active | #E9E9EB | 导航激活 / hover |

| --ink-3 | #A2A2A8 | 占位符 / 细线图标 |

**字体：** 标题衬线 `Georgia, "Times New Roman", "STSong", "SimSun", serif`；正文无衬线 `-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。层级：hero 大标题 40px 衬线；顶栏/路径标题 20px 衬线；阶段标题 18px 衬线；任务标题 14px 无衬线 600；正文 14px/1.6；次级 12.5px。对比 = 衬线大标题 vs 无衬线小正文、近黑 vs 灰。

**间距与留白：** 侧栏宽 260px、内边距 20/16px；导航项高 44px、圆角 10px、项距 4px、分组距 24px；主内容限宽 960px 居中；hero 上留白约 12vh；卡片内边距 20-24px、卡片间距 16px、模块间距 32px。呼吸感 = 留白优先于边框，不堆叠密集块。

**组件样式：**
- 主按钮：--accent 实底、圆角 10px、白色图标/文字、无边框无阴影（参考图发送钮形态）。

- 导航激活项：--bg-active 填充圆角块（10px）。
- quiz 选项行：发丝线圆角行，hover --bg-active；选中 = --accent 描边 + --accent-soft 底。
- 进度条：6px 全圆角，track = --line，fill = --accent。
- 输入容器：大圆角 18px 卡片 + 内部动作行（还原参考图 "How can I help you today?" 卡）→ 新目标一句话输入用此形态，右下 periwinkle 生成钮。

**整体布局（参考图结构映射三区）：**
