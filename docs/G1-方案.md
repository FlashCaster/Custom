## 1. 核心数据结构（签名级）

```py
Goal  { id, statement, interests: [str], created_at }
Path  { id, goal_id, title, stages: [Stage], status: "draft"|"active"|"done" }
Stage { id, title, tasks: [Task] }
Task  { id, stage_id, kind: "quiz"|"artifact", title, brief,
        difficulty: 0|1|2|3,            # N0~N3，MVP 由系统推荐生成
        quiz?: { q, options: [str], answer: int, explanation },
        acceptance: [str], skills: [str] }
Attempt { id, task_id, ts, difficulty, result: "pass"|"fail", evidence }
# 进度 = Path 派生；难度推荐规则见下
```

## 2. 系统推荐难度规则（MVP）

- 无历史 → 推荐 **N1**；连续 2 次同难度 pass → 升 1 级（≤N3）；fail → 降 1 级（≥N0）
- 每次 quiz 的 difficulty 快照进 Attempt（防路径改版后历史失真）
- 接口预留 `difficulty` 参数（自选难度后做，MVP 不暴露 UI）

## 3. 模块划分

```
backend/main.py       FastAPI 路由：goals/paths/tasks/attempts/export
backend/planner.py    DeepSeek 生成候选路径（含难度标注）→ 严格 JSON 校验 → draft
backend/checker.py    quiz 判分 + 难度推荐规则 + 验收清单确认
backend/store.py      SQLite（sqlite3 标准库）CRUD，参数化
frontend/index.html   原生单页三区：左导航（当前置顶）| 主区任务 | 右上角进度条
frontend/app.js       fetch API + 渲染（转义）+ 提交判定
data/custom.db
```

## 4. 技术选型

- 后端：FastAPI + uvicorn + sqlite3 标准库，pytest
- LLM：**DeepSeek 官方 SDK**（`pip index versions deepseek` 验证官方源；若官方无独立 SDK 则用 openai SDK 指向 `api.deepseek.com`——两者同协议，实施时以验证结果定）
- 前端：**原生 HTML/JS 单页，零框架零构建**（用户决定）——理由：功能只有三区布局+列表+表单+进度条，无复杂状态；零 node 依赖链，保持"一条命令启动、本地即用"的简洁哲学；FastAPI 直接伺服静态文件

## 5. 测试策略

- `test_planner.py`：mock LLM → 路径解析（坏 JSON/缺字段/难度越界 0-3/超长/非预期结构全拒）
- `test_checker.py`：quiz 判分（空白/大小写/越界 answer/空选项）+ **难度推荐**（无历史→N1 / 连续 2 pass→升级 / fail→降级 / N0 下限 / N3 上限）
- `test_store.py`：CRUD + 级联 + 并发
- `test_api.py`：路由 + 2.4 八大类边界
- 每任务类型 ≥3 正常 + ≥10 攻击用例
