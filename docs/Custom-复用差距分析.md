# Custom 现有代码库 → 新定位（通用学习系统）的复用/差距分析

> 状态：分析稿（供功能设计参考；不依赖待确认的 D1/D3）
> 建立：2026-09-02
> 底座：`docs/Custom-定位与需求-v2.md`（新定位草案）+ `backend/*`（现有实现）
> 目的：明确现有代码哪些能**直接复用/改名复用**，哪些**是新做**，避免推倒重来或重复造轮子。

---

## 一、现有代码库是什么

现有 Custom 是"**个性化学习路径生成器**"：FastAPI + SQLite + 原生前端；`store/schema`（goals→paths→stages→tasks→attempts，外加 placement_tests/conversations）；`planner`（LLM 生成候选路径）、`checker`（quiz 判分 + 产出物清单）、mastery 引擎设计（θ 单题估计，未接线）。

---

## 二、概念映射：现有实现 → 新通用学习系统

| 新分层 | 新语义 | 现有实现 | 复用性 |
|---|---|---|---|
| **目标层** | 你去哪（倒着写结果："我学会了…"） | `goals`（statement/interests） | ✅ 直接复用（改语义=目标陈述） |
| **循环层** | 问题→猜想→验证→输出 | — | 🆕 新做（这是学习循环元模型） |
| **验证层·证据** | 每日两勾 | `attempts`（result pass/fail + evidence） | 🟡 复用结构，语义改为"每日勾" |
| **验证层·输出** | 讲题卡（四格：考什么/为何/卡在哪/下次信号） | `tasks`（quiz/artifact）+ `attempts.submission`（artifact 文本） | 🟡 复用 submission 载体，需加"四格"结构化字段 |
| **验证层·验收** | 判定卡（岔路口三率，不用百分制） | `checker.judge_quiz` / `confirm_acceptance`（清单） | 🟡 需改造：quiz 判分 → 岔路口复述/讲通判定；mastery（θ）语义需定 D3 |
| **内容层** | 自顶向下（锚点题→拆解→补概念→求解→验证→方法卡） | `planner.generate_candidate_path`（路径生成）+ `stages/tasks` | 🟡 结构骨架可复用，但内容范式(八步)需落进生成逻辑；数学题源来自高考数学工作区 |
| **习惯层** | streak / AI 提醒 / 80% 吸引力 | — | 🆕 新做（streak 状态 + 提醒调度） |
| **动机层** | 方法托管动机 + 意义感 | — | 🆕 新做（或复用"学习动机与方法"文案内容） |

## 三、结论：哪些值得保留，哪些是新增

### 保留 / 改名复用（不推倒）
- **Schema 骨架**：`goals/paths/stages/tasks/attempts` 层级仍适用"目标 → 系统 → 环节 → 行动 → 判定"，**改名语义**即可（不必重写 CRUD）。
- **`store` 的 CRUD + 参数化 + 外键级联 + 错误约定**：全部可直接复用，只加新表/新列。
- **`main.py` 错误映射 + LLM client 工厂 + 静态伺服**：通用，直接复用。
- **`checker.judge_quiz`**：若 D3 保留 quiz 判分，可复用；若弃 quiz，迁移/改造。
- **`placement_tests` / `conversations`**：作为内容层的可选组件可复用。

### 新增（现有没有的）
- **判定卡 / 岔路口验收模型**（看懂率=复述岔路口≥一半、讲对率=骨架+扛住追问+卡壳自指；**不用百分制**）——这是 Custom 最值钱的资产，现有判定是"quiz 对错 + 清单全勾"，**没有"讲通/复述"型验证**。
- **讲题卡四格结构化 + 每日两勾的连续/进度**（streak 状态 + 日历/连续天数）。
- **习惯层**：streak 可视化、AI 提醒时机/文案、7 天停推、被动攻击式沟通。
- **内容范式引擎**（自顶向下八步生成/校验）：锚点题选题标准、拆解表、按需补概念、方法卡。
- **单用户本地**（现有即单机无 user_id，契合"自用 + 分享身边人"）。

---

## 四、需要定夺的映射缺口（对应需求文档 D1/D3）

1. **D1 复用程度**：把高考数学工作区方法论直接当 Custom 骨架（A），还是 Custom 独立设计、高考数学只当内容（B）。
2. **D3 验证维度**：现有 quiz 对错 / artifact 清单（判别式），与判定卡"岔路口三率"（懂不懂/讲不讲得出），与 mastery θ（能力估计）——三者关系（保留/合并/分层）。
3. **"内容通道"如何进系统**：锚点题/例题/题源从哪来（高考数学工作区教案/lessons/5·3 真题），是否由 LLM 按自顶向下范式生成还是复用已有成品。

---

## 五、功能设计建议（倾向，供 D2 定夺）

- **v0 = 通用系统骨架（六层最小闭环）+ 高中数学作为第一条内容通道**。先跑通"目标 → 四拍循环 → 每日两勾 → 讲题卡 → 判定卡验收"这一条最小路径，再扩内容通道。
- **判定卡验收先做成 "AI 辅助 + 用户自评" 双轨**（单用户、无老师时，AI 按岔路口标准给判定 + 用户可质疑），避免过度依赖"老师在场"这一人工前提。
