# ADR：checker 判分契约（quiz 答案双模 + 坏数据/坏输入二分）

- 日期：2026-08-20
- 状态：已确认
- 影响范围：backend/checker.py、frontend/app.js（提交形态）

## 背景

G1 §5 对 `test_checker.py` 的边界要求包含「空白/大小写/越界 answer/空选项」，而 G2 stub 将
`judge_quiz` 的入参定为 `answer: object`（非具体类型）。需要明确：用户提交答案的形态，以及
「非法输入」到底该抛错还是返回判分结果。

## 决策

1. **quiz 答案 = 双模**：`answer` 既可是**索引 int**（含纯数字串如 `"0"`），也可是**文本 str**
   （大小写不敏感、去首尾空格，匹配正确选项文本 `options[answer]`）。
2. **坏数据抛错、坏用户输入返回 fail 二分**：
   - 坏数据（quiz 非 dict / options 空 / answer 越界）→ 抛 `ValueError`，属系统缺陷，由 planner
     第 4 步校验兜底，checker 仅作防御性兜底。
   - 坏用户输入（空白 / 越界索引 / 错文本 / 错误类型）→ 返回 `{"result": "fail"}`，是正常交互，不崩。

## 后果

- 前端提交可灵活用索引或文本，用户体验更宽容（输错大小写/带空格也能判对）。
- 判分逻辑多一条文本匹配分支，需额外覆盖「大小写/脏数据/特殊字符」用例（已在 G3-3 计划用例表 A06/A07）。
- 契约已写入 `docs/G3-3-checker计划.md` §2.1 与 §5。
