# ADR-2026-08-20-领域与形态

- 日期：2026-08-20
- 状态：已废弃（替代：ADR-2026-08-20-Custom方向确立.md）

## 背景
research.md 五路调研确认"AI 教学不可验证"是最大缝隙，但四个机会点是四个不同的产品，必须收敛。G0 立项 grill 定下：目标用户是求职者本人（dogfooding），4 周后要能在 AI 时代笔试（需求实现型任务）中稳定交付。

## 决策
v0 = **"AI 时代笔试能力训练场"**，一个 DSH 插件：
1. 领域：需求实现型代码题（非算法 OJ），数学题后扩展
2. 形态：DSH 插件（toolkit + ui-panel），后续扩展 Claude Code / Codex 插件
3. 做题形态：学生用外部 AI 工具完成，Truthy 只负责领题/判分/掌握度跟踪——**不教学、不辅导**
4. 判分输入：只交代码产物，跑题目自带测试用例
5. 题库：手工录入 + 结构化模板（5-10 题起步）
6. 判定器：v0 全部 L0 确定性检查，无 LLM judge
7. 掌握度模型：按**技能点**（源自《AI 编程工作流与 Prompt 模板》）而非按题，以支持后续 agent 知识点扩展

## 备选方案（含否掉的原因）
- 数学题领域 —— 否：判定器要自己写计算器，工程量翻倍；v0 后扩展
- 内置教学对话教练 —— 否：重蹈研究确认的"无护栏 AI 教学"覆辙；Truthy 的价值在验证不在教学
- LLM 自动生成题库 —— 否：AI 生成的标准答案不可信（循环论证），测试用例必须人工编写
- 判定输入含过程痕迹/git 日志 —— 否：v0 只判结果，流程合规判定后补（记录不判分）
- 评测工具/MCP server 形态 —— 否：是分发渠道/开发者面，不是 v0 产品；判分数据积累后作为副产品生长

## 影响
- 判分沙箱（执行学生代码）是核心安全组件，G1 方案必须优先设计
- gold set 与判定器一致率 ≥95% 是验收硬指标，判定器自身可验证
- 技能点 taxonomy 从工作流文档提炼，映射到每道题
- 后续扩展路径：数学题 → agent 知识点 → MCP/评测工具（数据已积累）
