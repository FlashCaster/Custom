# ADR：课堂拍照的访问与照片留存

- 日期：2026-09-16
- 状态：已采纳
- 范围：备课 MVP 第二阶段的课堂拍照、OCR 候选文本和 AI 反馈。
- 关联：`outputs/Custom备课MVP规格说明.md` 用户故事 29-33、测试决定中的课堂拍照流程。
- 票 #8 前置：本 ADR 的接口、状态和验收条件必须先实现并通过。

## 背景

教师在电脑上为当前教学活动显示二维码，学生的手机打开拍摄页。照片会包含学生作答内容，不能因为方便识别而泄露给错误的活动、其他局域网设备或留存政策不清楚的服务商。

现有产品是本地 Web、SQLite 和用户自带模型密钥。已有安全规则要求外部输入不可信、上传目录不静态伺服、动态页面不把不可信内容作为 HTML 写入。本功能沿用这些规则。照片与已确认的文字也不是同一类数据：照片只在识别和教师核对期间暂存，确认后持久化的只有文字和课堂记录。

## 决策

### 访问边界

主应用继续只监听 `127.0.0.1`。教师点击“为当前活动拍摄”后，应用才在教师选定的私有局域网地址启动一个临时 HTTPS 监听器。该监听器只提供拍摄会话的页面和上传端点，不提供教师页面、SQLite 导出、静态文件、通用 API 或其他教学活动。

二维码编码完整的 HTTPS URL：

```
https://<当前局域网地址>:<临时端口>/capture/v1/<opaque-token>
```

`opaque-token` 由至少 32 个随机字节生成，使用 URL-safe Base64 编码。数据库只保存它的 SHA-256 摘要，不能保存原始令牌。URL 不包含学生姓名、备课稿 ID、活动标题、题目、图片名或可枚举的整数 ID。拍摄响应必须设置 `Cache-Control: no-store`、`Referrer-Policy: no-referrer` 和禁止第三方资源的 Content Security Policy。应用日志不得记录完整 URL、令牌、图片字节、OCR 候选文本或 EXIF。

手机在课前与此本地 HTTPS 证书建立信任。证书必须含当前局域网地址的 Subject Alternative Name，私钥只保存在本机的 `data/` 运行时目录，且不进入版本库。应用每次启动拍摄监听器前都要验证该地址不是公网地址或回环地址。教师不能建立可信 HTTPS 连接时，应用不显示可用二维码，直接进入人工输入或教师追问。不得以 HTTP、公共反向代理、隧道服务或云中转作为替代。

二维码只是进入拍摄等候页的能力令牌，不能阅读活动内容。扫码后，手机只显示会话短码和“等待电脑确认”。电脑端显示同一个短码和当前活动编号；教师核对后才批准该设备打开相机。短码是会话确认，不是认证凭据。手机不提交活动 ID，服务端从会话记录决定活动关联。

### 会话和错扫处理

每份备课稿同时只能有一个开放的拍摄会话。创建新会话、切换当前活动、教师点击结束、应用重启和过期都会关闭原会话。服务端使用下面的状态，所有状态转换在服务层检查并以事务保存：

| 状态 | 允许的下一状态 | 规则 |
| --- | --- | --- |
| `issued` | `claimed`、`closed`、`expired` | 二维码签发后最多 5 分钟可扫码。 |
| `claimed` | `approved`、`closed`、`expired` | 手机认领后，教师有 60 秒核对并批准。 |
| `approved` | `uploaded`、`closed`、`expired` | 仅该设备可在 2 分钟内上传一张照片。 |
| `uploaded` | `ocr_ready`、`fallback`、`cleanup_needed` | 上传收讫开始 3 分钟识别时钟。 |
| `ocr_ready` | `confirmed`、`fallback`、`cleanup_needed` | 教师可查看图片和候选文字，原图最多再保留到上传后 10 分钟。 |
| `confirmed` | `closed` | 原图删除成功后才写入确认文字。 |
| `fallback`、`closed`、`expired` | `cleanup_needed` 或终态 | 不再允许上传或发送 OCR 候选给 AI。 |
| `cleanup_needed` | `closed` | 应用重试删除成功后关闭。 |

服务端在请求时重新检查会话状态、活动 ID 和过期时间，不能只依赖前端计时。已关闭、过期、非当前活动或已经上传的令牌一律返回相同的“二维码已失效，请使用电脑上的当前二维码”页面，不泄露原活动。另一个手机认领、重复上传、活动切换后的旧码和延迟到达的上传都不能改变当前活动。教师必须重新签发二维码才能重拍。

拍摄端必须限制为一张图片，校验请求体大小、实际 MIME 类型和像素上限，并拒绝动画、文档和图像解码失败的内容。服务端以生成的会话 UUID 决定临时文件名，永不使用客户端文件名。拍摄文件目录不静态伺服，且不进入数据导出。

### OCR 和照片留存

本 MVP 不把照片上传到任何云端 OCR、视觉模型或其他第三方服务。当前没有一份经核实、可执行的供应商照片留存结论，因此这种上传默认禁止。OCR 只能由本机进程和本机模型完成。实现时还必须核实本地 OCR 依赖的官方来源、版本、许可证和离线运行方式；核实失败时不启用 OCR，走人工输入。

应用把收到的原图放在专用临时目录。它不得写入 SQLite、导出包、浏览器缓存、缩略图缓存、日志或备份。应用在读入时丢弃 EXIF 和原始文件名。OCR 候选文字只存在于进程内存和已批准的教师页面，不能写入数据库、模型提示或课堂观察。应用重启时先扫描临时目录并删除遗留图片，再恢复其他服务。

教师核对并编辑候选文字后，确认操作按以下顺序执行：

1. 应用删除该会话的原图，并确认删除调用成功。
2. 应用在 SQLite 事务中写入教师确认后的文字、课堂记录和 `photo_deleted_at`。
3. 之后才允许教师主动把确认文字用于课堂 AI 提示。

删除失败时，应用把会话标为 `cleanup_needed`，显示持续告警并提供重试。它不能保存 OCR 候选文字、不能把候选文字发送给 AI、不能把该会话标为已确认。应用在启动、会话结束和用户点击重试时再次删除。图片删除后而文字写入失败时，应用保留浏览器内的已编辑文字供教师重新提交，但不恢复照片，也不自动把文字写入数据库。

普通文件系统删除不能承诺抹除存储介质上的可恢复数据。这里的责任是应用删除自己持有的服务器临时副本，并记录删除结果；手机操作系统或浏览器自行保存的相机文件不在应用控制范围。拍摄页应只使用浏览器相机采集，不提供相册选择或下载按钮，并明确提示教师不要另存照片。

未来若考虑云端 OCR，必须另开 ADR，并在启用前保存可复核证据：服务商版本化的数据处理条款、照片是否用于训练、明确的保留期限与删除控制、处理地区和分包商、账户级配置的实际验证记录。任一项无法核实时，产品不得上传照片。即使通过核实，云端路径也需要单独的用户启用开关和端到端删除测试，不能作为本 MVP 的故障回退。

### 课堂失败回退

上传开始后 3 分钟内没有可用的 OCR 候选文字，应用取消识别，删除原图并把会话标为 `fallback`。教师立即回到口述、键入或教师稿中的人工追问，并记录实际耗时和 `ai_not_used` 或相应失败原因。网络不可用、证书未受信、扫码错误、设备未获批准、图片校验失败、本地 OCR 不可用和模型不可用都走同一课堂回退，不等待恢复。

人工输入不是 OCR 候选。教师可直接键入学生原话，确认后按普通课堂记录保存。若该会话已经收到照片但删除还失败，系统先要求完成图片清理；在清理成功前，不能把该会话的文字作为确认结果或 AI 输入。教师仍可继续使用纸面任务和人工追问，不让课堂停住。

AI 只接收教师确认后的文字和教师显式选择的必要活动上下文，从不接收照片。AI 的输出仍是待教师选择的一条候选意见，不能直接显示给学生。模型服务对确认文字的政策不由本 ADR 改写；调用它仍受产品既有的用户主动调用、候选不可信和教师终裁约束。

## 实现契约

票 #8 至少需要以下边界，名称可按代码风格调整，语义不得省略：

- `create_capture_session(lesson_plan_id, current_activity_id)` 只能为当前活动创建会话，关闭同一备课稿的旧会话，并返回二维码 URL 与短码。
- `claim_capture_session(token, device_nonce)` 只建立待批准设备，返回不含活动内容的等候结果。
- `approve_capture_session(session_id, short_code)` 只允许教师端调用，并签发绑定设备的短时上传凭据。
- `upload_capture_photo(token, upload_credential, bytes)` 从会话派生活动关联；请求体不能指定或覆盖活动 ID。
- `confirm_ocr_text(session_id, text)` 必须先完成原图删除，随后才在一次数据库事务内持久化文字和删除时间。
- `close_or_cleanup_capture_session(session_id, reason)` 必须幂等，关闭会话并删除临时文件；删除失败返回可观察的 `cleanup_needed`。

存储层应记录会话 UUID、备课稿和活动关联、令牌摘要、状态、签发和过期时间、删除状态与时间、失败原因和课堂耗时。它不得记录原始令牌、图片路径以外的图片内容、EXIF、原文件名或未确认 OCR 文字。临时文件路径可由固定私有目录和会话 UUID 推导，不能接受用户输入的路径。

## 票 #8 验收条件

1. 主应用只在回环地址提供教师功能。二维码打开的 HTTPS 监听器无法访问教师路由、静态文件、导出和非拍摄 API。
2. 二维码令牌不含个人信息或活动内容，数据库只存令牌摘要。缺失、篡改、旧、过期、非当前活动和重复令牌均不能上传，并返回同一失效结果。
3. 手机必须完成电脑端短码确认。未经批准的设备、第二台设备和活动切换后的设备不能取得上传权限；上传请求中的活动 ID 即使伪造也无效。
4. 会话按 5 分钟签发、60 秒批准、2 分钟上传和上传后 3 分钟 OCR 时钟执行。测试使用可控时钟，覆盖每一个超时边界。
5. 测试证明照片不会离开本机：替身 OCR 进程只接收本地文件或字节，网络拦截器观察不到对 OCR 或视觉服务商的请求。未验证供应商配置时，配置校验拒绝启动云端 OCR。
6. 教师确认前，候选文字不在 SQLite、导出、日志或模型请求中。确认后，持久化记录只含确认文字和删除时间，不含图片、缩略图、EXIF 或原文件名。
7. 成功确认先删除服务器原图，再写入确认文字。删除失败、应用重启、识别超时、取消和会话关闭都触发删除；失败状态可见且会重试。测试在删除失败时断言没有确认文字和模型调用。
8. 本地 OCR、HTTPS 配对、上传或 AI 任一环节不可用时，界面在三分钟内给出人工追问、口述或键入的可操作入口，并在课堂记录中保存失败原因和实际耗时。
9. 在真实教师手机上完成一次 HTTPS 证书信任、扫码、短码批准、拍摄、删除和人工回退走查。该走查是上线前条件，自动化测试不能替代它。

## 后果和剩余风险

本决策增加了本地 HTTPS 配对、临时监听器和删除失败处理的实现量，但避免把学生作答照片交给留存政策未知的服务商。教师需要在课前完成一次设备证书信任；无法完成时只能使用人工回退。

本地 OCR 的识别质量、不同手机浏览器对本地 HTTPS 和相机权限的支持、以及本地删除在具体操作系统上的行为仍需实测。文件系统删除无法消除底层介质恢复风险。任何云端 OCR 的使用仍未获批准。
