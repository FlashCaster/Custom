# ADR-2026-08-20-Custom方向确立

- 日期：2026-08-20
- 状态：已采纳（**替代** ADR-2026-08-20-领域与形态.md）

## 背景
G0 grill 三轮后，用户方向修正：v0 从"DSH 插件判分训练场"变为"本地 Web 个性化学习助手"。原 v0 判分训练场降级为 Custom 内部的完成检查器（辅助角色），Truthy 名称被 Custom（暂定）替代。

## 决策
1. 项目更名 **Custom**（暂定）；Truthy 成为其子概念 = 完成检查器
2. 形态：**本地 Web**（Python FastAPI + SQLite + 前端），无服务器、数据全在用户本地、用户自带 LLM API key
3. 核心体验：定制层（一句话目标/职业 → 兴趣点 → 学习路径）+ 执行层（任务引导：左侧当前阶段+任务置顶、右上角总进度实时推进、完成即更新下一任务，游戏化达成感）
4. 完成判定 = **轻验证**：可机械验证任务自动判（判分器降级为完成检查器）+ 开放产出任务（项目/文档）验收清单确认；禁止纯人工打卡
5. 模型角色 = **路径/任务生成器**：LLM 生成候选，用户确认后落地（"所有选择透明"原则 = 防幻觉机制）；不内置辅导对话、不用 LLM 做验证
6. 产出原则：所学必有产出（每阶段 ≥1 个项目或文档；视频后扩展）
7. 循环评估：阶段 = 技能点掌握度 + 产出清单，直到达标用户最初目标
8. 功能：可输入实际问题（如面经）→ 针对性训练

## 备选方案（含否掉的原因）
- DSH 插件形态 —— 否：形态转换成本高，目标用户是大众学习者而非 DSH 用户；技术栈从 TS 插件转为 Python Web（与求职栈一致，简历价值更高）
- 纯人工确认完成 —— 否：回到研究缺口 3（"学会了"不可观测），与 research.md 核心主张断开
- LLM 全自动验证 —— 否：AI 验证 AI 循环论证
- 内置辅导对话 —— 否：v0 聚焦"路径 + 执行 + 验证"，辅导后扩展
- 判分训练场作为执行层核心 —— 否：产品主交互是任务引导与进度达成，判分是完成检查而非主场景

## 影响
- 技术栈变更：TypeScript DSH 插件 → Python FastAPI Web；原插件生产线不再用于本项目壳层（判分逻辑仍可模块化复用）
- 完成检查器保留 gold set 验证（一致率 ≥95% 验收指标不变）
- LLM 生成 + 用户确认 = 防幻觉机制，写入安全清单（LLM 输出不可信）
- 游戏化进度（右上角总进度/左侧当前任务）成为 v0 UI 核心，前端布局由此驱动
- 后续扩展路径：数学题 → agent 知识点 → 真实笔试对接 → 视频产出验证

## 修订记录
- 2026-08-20：v0 聚焦场景从"AI coding 笔试能力训练"调整为 **AI 工程师所需技能知识点**（LLM 基础/提示工程/RAG/Agent/MCP/评测/AI 工程化）。连锁影响：①任务形态 = 知识点任务（学习 → quiz 过关 or 产出物验收），不再跑需求实现型判分；②判分沙箱后置，v0 不执行学生代码；③验收指标从"检查器一致率"改为"quiz 质量抽查 ≥20 道 + 人工复核记录"；④技能树来源 = 求职 JD 调研 + 《AI 编程工作流与 Prompt 模板》。
